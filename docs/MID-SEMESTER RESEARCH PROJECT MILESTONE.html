PROBLEM AND RESEARCH OBJECTIVE Problem: Existing dermatology AI systems lack simultaneous support for (a) large-scale African skin-tone data, (b) clinician-in-the-loop (HITL) reinforcement learning, (c) operational fairness monitoring, and (d) integrated web-first deployment with telemetry. In Uganda (Uganda Cancer Institute, Mbarara Hospital), these gaps prevent reliable clinical adoption. Objective: Investigate whether a concept-bottleneck interpretability framework combined with HITL reinforcement learning improves both diagnostic reliability and fairness under limited-label, low-bandwidth clinical settings compared with standard transfer-learning baselines.

WHAT EXISTS, THE GAP, AND PROPOSED CONTRIBUTION Previous studies have investigated convolutional networks (ResNet, HRNet via timm), pretrained vision models, data augmentation (albumentations), fairness debiasing (CIRCLe, Skin-Deep-Unlearning), and foundation models (PanDerm, Derm1M, DermFM-Zero) for dermatology classification. Key references establishing the landscape: [1] Corrected-Skin-Image-Datasets (Nature Scientific Data 2025) — identified duplicates in HAM10000 and mislabeled Fitzpatrick types in Fitzpatrick17k; cleaning is retrospective. [2] MONET (concept bottleneck / transparency) — provides concept-level explanations but freezes concepts after training; no RL/HITL loop. [3] CIRCLe / Detecting-Melanoma-Fairly — address color-invariant representations and skin-tone detection, but fairness intervention is training-time only with no operational fairness monitor. Limitations of existing work: Western-centric pre-training data; no real African skin-tone scale; no clinician feedback loop after deployment; no telemetry in low-bandwidth settings; cleaning is retrospective rather than prospective. Proposed contribution: A unified pipeline that (1) ingests and curates African skin-type dataset sources (HAM10000, Fitzpatrick17k, ISIC2019/2020, synthetic); (2) implements a concept-bottleneck model (7 concepts → 3 classes + 6 Fitzpatrick types) with explainable activations via captum; (3) closes the HITL loop with PPO-style RL (rl_module.py / hitl_pipeline.py) so clinician feedback updates predictions; (4) monitors fairness operationally (metrics_tracker.py, datasetEquity.py); and (5) delivers through a web-first interface (FastAPI server + Gradio + HTML dashboard) ready for low-bandwidth deployment.

FULL RESEARCH PIPELINE / PROPOSED ARCHITECTURE Input data / source: - Skin-lesion images (HAM10000, Fitzpatrick17k, ISIC2019/2020, synthetic) plus metadata (Fitzpatrick type 1–6, patient demographics). - Synthetic/mock cases generated for safe HITL testing (main.py generate_mock_cases; seed_demo.py). Processing pipeline: 1. Preprocessing / augmentation — albumentations, OpenCV melanin normalization (samplesEquity.py), duplicate/mislabel cleaning. 2. Concept-bottleneck encoding — CNN backbone (torchvision / timm) → 7 interpretable concept embeddings (model.py). 3. Diagnosis mapping — fully connected head to 3 classes with Fitzpatrick awareness; explainability via captum (Integrated Gradients). 4. HITL / RL — clinician provides feedback (correct / incorrect / corrected label); case stored as Case object (rl_module.py); PPO-style update (hitl_pipeline.py). 5. Fairness & metrics tracking — datasetEquity checks representation; metrics_tracker persists case_history.json / case_history.csv; activity.json tracks events. 6. Web interface — Gradio quick interface (ui.py / main.py --ui); FastAPI REST server (server.py) with bcrypt auth, UUID sessions, endpoint routing; HTML dashboard (dashboard.html) for clinician viewing and export. Outputs: (a) diagnosis with concept-level explanation; (b) updated model weights after clinician feedback; (c) fairness metric reports; (d) exported case histories (CSV / JSON); (e) telemetry via server logs / render.yaml deployment. What is new / under investigation: The combination of concept-bottleneck interpretability with an operational HITL RL loop and real-time fairness monitoring in a web-first deployment is the research focus — not simply applying ResNet50 to HAM10000 and reporting accuracy.
